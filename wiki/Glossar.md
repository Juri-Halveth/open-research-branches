# Glossar · Begriffe schnell finden

[Start](Home.md) · [Alle Projekte](Projekte.md) · [Belege & Zeitlinien](Belege-und-Zeitlinien.md)

Die Begriffe helfen beim Lesen der Projekte. Wo ein Programm einen Ausdruck genauer definiert, gilt der dortige versionsgebundene Vertrag.

| Begriff | Bedeutung in dieser Sammlung |
| --- | --- |
| **Agency** | Handlungsspielraum einer Person oder Figur im jeweils beschriebenen Kontext. |
| **Anker** | Eine benannte Referenz auf einen Inhalt, Zeitpunkt oder Datensatz. Welche Beziehung sie trägt, muss einzeln beschrieben sein. |
| **Ast / Branch** | Hier meistens ein eigenständiger Projektordner unter `branches/`. Das ist von einem Git-Branch wie `main` zu unterscheiden. |
| **Audit** | Nachvollziehbare Prüfung einer definierten Frage anhand benannter Quellen und Regeln. |
| **Audit Star** | Index der katalogisierten Dateien und ihrer belegten Querverweise. Die Verbindungen sind Navigationshilfen. |
| **Claim / Aussage** | Der konkrete Satz, der geprüft oder vertreten wird. |
| **Claim Ceiling / Aussagegrenze** | Die stärkste Aussage, die der jeweilige Arbeitsstand trägt. |
| **Commit** | Ein Git-Objekt, das einen Dateistand und Metadaten mit seinen Vorgängern verbindet. |
| **Credit** | Anerkennung eines konkreten Beitrags; Art und Umfang richten sich nach Beitrag, Quelle und gegebenenfalls Vereinbarung. |
| **Fixture** | Festgelegte Beispieldaten für einen Test; die öffentlichen Werkzeuge verwenden häufig synthetische Daten. |
| **Gegenmodell** | Eine andere Erklärung oder Gestaltung, mit der derselbe Gegenstand verglichen wird. |
| **Hash / Digest** | Ein aus Daten berechneter Prüfwert. Er unterstützt den Vergleich gebundener Dateifassungen. |
| **Hypothese** | Ein vorgeschlagener Zusammenhang, dessen unterscheidende Prüfung noch aussteht oder fortgeführt wird. |
| **Modell** | Eine definierte Darstellung ausgewählter Eigenschaften eines Gegenstands. |
| **Namensraum** | Kontext einer Bezeichnung, etwa `LUCINET::ASTER`, der gleichlautende Namen auseinanderhält. |
| **Provenienz** | Dokumentierte Herkunft und Verarbeitung eines konkreten Inhalts oder Artefakts. |
| **Receipt** | Strukturierter Beleg eines benannten Vorgangs oder Prüfstands mit seinen Referenzen. |
| **Referent** | Der konkrete Gegenstand, auf den sich eine Aussage bezieht. |
| **Release** | Veröffentlichte Fassung, gewöhnlich mit Tag und gegebenenfalls gesonderten Artefakten. |
| **Reopen-Trigger** | Genau benannte neue Quelle oder Änderung, bei der eine zurückgestellte Prüfung fortgesetzt werden kann. |
| **Snapshot** | Gebundener Ausschnitt eines Zustands; sein Umfang und seine Zeitquelle gehören dazu. |
| **These** | Ein zur Diskussion gestellter Erklärungs- oder Gestaltungssatz. |

## Häufige Statusangaben

| Status | So lässt er sich lesen |
| --- | --- |
| `OBSERVED` | Innerhalb des benannten Beobachtungsumfangs direkt festgestellt. |
| `USER_REPORTED` | Als Nutzerangabe dokumentiert; die Quelle belegt zunächst die Aussage. |
| `STRONGLY_SUPPORTED` | Durch die gebundenen Quellen stark gestützt, im erklärten Scope. |
| `INFERRED` | Eine aus Quellen gezogene Schlussfolgerung. |
| `UNKNOWN` | Für diese Frage fehlt derzeit eine Entscheidung tragende Zuordnung. |
| `NOT_PROVEN` | Der benannte stärkere Schluss ist mit dem vorliegenden Material nicht nachgewiesen. |
| `FINITE_SNAPSHOT` | Die Prüfung hat einen endlichen, dokumentierten Umfang und Stand. |
| `PUBLIC_DERIVATIVE` | Ein eigenständig veröffentlichter Ableger mit eigenem Veröffentlichungsscope. |
| `HOLD_IMPLEMENTATION` | Die beschriebene Umsetzung ist zurückgestellt; Entwurf und offene Voraussetzungen sind erhalten. |

Die Statusangabe gehört immer zu einer konkreten Aussage und Fassung. Ein erfolgreicher Strukturtest bestätigt die getesteten Regeln; er ersetzt weder die Prüfung einer äußeren Wirkung noch eine Zustimmung oder Rechtevereinbarung.
